# 四时人生 · 刘看山的生活大富翁

本地运行的横屏 2D 田园像素网页游戏，欢迎页标记为「田园三选版 · v4」。刘看山沿四季小镇的连续路线投骰前进，在实际落点体验生活事件。每个事件都有三个回应；选择前不显示资金、情绪、专业变化，选择后才揭晓结果并写入本局手记。抵达终点或情绪归零，均可查看复盘及相近的知乎讨论。

## 开始体验

在项目目录双击 `启动游戏.cmd`，或在终端执行：

```powershell
.\启动游戏.cmd
```

需要 Node.js 22.12 或更新版本。默认地址为 [本机游戏](http://127.0.0.1:4173/)，仅监听本机；这个地址不是可发给外地队友的公网链接。入口会检查 `/api/health`，复用已运行的本项目服务；如果端口被其他程序占用，则明确报错。日志保存在项目 `test-results/`，后台服务不依赖启动窗口保持打开。

只启动、不打开浏览器，以及自选端口：

```powershell
.\启动游戏.cmd -NoBrowser
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-game.ps1 -NoBrowser -Port 4180
```

手动开发：首次 `npm install`，随后 `npm run dev`。生产预览：先 `npm run build`，再 `npm start`。手动启动可用 `PORT` 环境变量指定端口。当前场景使用 Canvas 2D，不依赖 WebGL；画布不可用时进入明确标注的地点列表备用模式。若看到旧版单选，请确认使用此项目启动入口，并用 Ctrl+F5 刷新；仅凭旧网页不能判断磁盘代码版本。

开局可以自定义角色名，并选择一种天赋：

- 稳健防守：首次在第13格遭遇甩锅的负面情绪消耗由留痕备忘录抵挡一次。
- 锐意进取：正向专业收益增加20%，负面情绪消耗增加10%；界面显示结算后的真实变化。
- 乐天知命：跨季恢复15情绪，不超过当前上限；恢复会写入下一次落点结算。

部分事件的分支取决于专业积累，采用确定性规则，不在后台偷偷抽取成功率；本版依用户要求在选择后才揭示结果。阶段门槛不足仍有继续准备的路径，不会卡死。所有数值、结果和天赋效果都是虚构游戏规则，不是心理测量、实际工资预测或职业保证。

### 演示节奏

完整路线无提前结束时平均约11.90次投骰，最少7次、最多40次；快速路线平均约3.91次投骰，最少2次、最多12次。快速模式是压缩节点后的随机体验，并非依次观看全部关键事件的导览，实际移动路径可能跨过原地图多个地点。

完整体验目标为 **6–10分钟**，快速体验目标为 **1–3分钟**。这是设计估计，尚非真人测量；玩家阅读速度、骰点、暂停和跳过动画都会影响时长。不能保证固定通关时间或一局看完8段动画。旧版双选的模拟通关率不应套用于本版三选规则，仍需真人试玩调节。

默认开启“自动出发”。角色先投骰、行走、完成到站转场；有动画的地点先播放片段，再停在中央选择卡，绝不代替玩家选择。关闭自动出发后，在准备状态按空格或点“继续前行”。查看规则／来源、切到后台或进入手机竖屏时暂停相应流程。

## 横屏场景、视觉资源与八段动画

最新六张参考图迭代：刘看山已改为白灰梨形身体、尖耳、大黑鼻、黑色手臂与靴脚、背面圆尾，支持正面／左右侧／背面，去掉旧背包与粉腮红。图书馆、体育馆、城中村和咖啡书摊的生成稿暂存于 `docs/art-drafts/`；两次图片仍无真正透明通道，因此新建筑接入开关暂时关闭，游戏继续使用原有建筑。详见 [参考图美术迭代](docs/参考图美术迭代-2026-09-09.md)。

40格的四季小镇采用俯视像素视角和连续弯曲道路，支持跟随角色、查看全图、拖动和缩放。场景有四季树木、花丛、湖泊小桥、菜园、不同屋顶的小屋、店铺、木栏、长椅和路灯。四季树木图集加载失败时自动使用程序绘制的树。顶部用金币、爱心和星形图标配合数字显示当前资源，选择后提供金币获得、心碎与专业变化反馈。

推荐16:9横屏。手机／平板竖向时显示旋转提示并暂停推进，不强制操作系统锁定方向；旋转回来继续。本轮按用户明确要求精修星露谷式田园像素方向；旧3D模块保留但不作为默认渲染器。美术依据、生成素材与提示词见 [本轮迭代说明](docs/像素美术与盲选迭代-2026-09-09.md)。

本轮8个动画格是 **6、11、13、15、18、22、27、31**。第8格保留普通到站转场，不占这次8个视频名额；所有事件现均有三个选项。

**正式视频尚未收到。** 当前使用带“临时演绎 · 正式动画待替换”标记的浏览器微缩分镜，约4秒；不能称为小雨已交付的成片，也不等于团队已批准最终“巴比特”风格。正式素材目标为横屏16:9、每段3–5秒，建议先确认第6格样片，再制作其余7段。

交付位置和清单：

`src/sources.js` 现有14条来源记录，保留先前8条并新增6条。8个动画格通过 `src/event-grounding.js` 逐一限定适用条件：6格有具体作者的讨论依据；第18格仅有相关提问、第31格具体作者待核对，两处会明确标注，不能宣称八格都已完成原文核实。其余事件保留主题关联。详见 [八格来源清单](references/practice-source-audit-2026-09-10.md)。不冒充作者真实经历，不生成“知乎统计比例”或所谓原话。

### 新增：试着说一句

第11格“报警声里的旧模块”与第13格“大群里的责任争执”，在三选一结算后提供可选陪练。虚构负责人/同事接着实际选择开场，玩家最多回应两轮，最后获得一句具体提示。每句最多240字符，可随时跳过；练习不改资金、情绪、专业或结局，不给人格评分。两处事件的旧AI点评改为展开后才请求，避免与练习自动争抢模型。

练习文字会发给知乎直答处理，不写入存档或手记，后端会话仅在内存短存（空闲10分钟过期、最多128项）。不要填入真实个人或公司秘密。故障时标注“预设练习 · 非实时AI”。详见 [本轮使用说明](docs/沟通陪练与事件依据-2026-09-10.md)。

后端根据骰子和选项重放整局，模型不能修改资金、情绪、专业或结局。事件请求去重、单并发；总结有一个等待位置，排队与生成共用45秒预算。每进程每UTC日最多80次新模型调用，缓存24小时、最多128项；重启会清空本地计数和缓存，这不是平台官方额度。

若每次停靠都请求一次事件叙事，再加最终总结，原叙事部分完整路线理论上界41次、快速路线13次；两个可选陪练若均完整参与，最多再增加4次，共用上述80次保护上限。实际受缓存、并发、提前结束与是否展开点评影响。主动点击“更多经验”另走搜索接口。模型与搜索凭据仅由后端／系统中已配置的 CLI 读取，不应写入项目或公开目录；可通过 `ZHIHU_CLI_PATH` 指定 CLI 路径。`GET /api/ai/status` 仅提供配置状态，不是成功调用或计费证明。

游戏内模型调用与用来开发游戏的 Codex 账号计费是不同系统；不能凭游戏接入代码保证开发任务走同一额度。

## 四季人生章节与配乐

| 季节 | 人生阶段 | 场景表现 | 原创循环配乐 |
| --- | --- | --- | --- |
| 春 | 初入社会 | 樱花、花瓣飘落 | 初芽来信：短笛与拨弦，100 BPM |
| 夏 | 努力打拼 | 浓绿树木、阳光与微光 | 向阳赶路：拨弦与轻打击，114 BPM |
| 秋 | 重新选择 | 暖色树冠、落叶 | 收好来时路：柔和钢琴与木琴，82 BPM |
| 冬 | 独立生活 | 雪地、飘雪、暖窗小屋 | 雪落仍有光：钟声与绵长和声，70 BPM |

新开局展示春季章节；跨季行走结束后，在事件卡之前展示约3秒的章节画面，可点击或按 Escape 提前进入。一次投骰跨过多个季节时按顺序展示，不增加额外事件或结算。人生阶段同时显示在地图左上角和事件标题栏；地图各季区域保留独立天气。

音乐是浏览器本地合成的4段16小节配乐，各自循环约34–55秒，不下载第三方录音、不调用模型。点击开始／继续存档后才尝试播放；如果浏览器阻止声音，点击右上角扬声器开启。跨季用0.8秒渐变切换；静音偏好保存在本机。切后台、打开弹窗、进入竖屏或结束游戏时暂停，回到可玩状态继续。详见 [四季声景迭代说明](docs/知乎关联与四季声景-2026-09-09.md)。

## 代码与存档

- `src/route.js`、`src/events.js`、`src/engine.js`：40地点、路线、三资源、天赋、结算和重放。

- `src/cinematic-manifest.js`、`src/cinematics.js`、`src/cinematics.css`：8段动画清单、播放与临时分镜。
- `src/season-chapters.js`、`src/season-chapters.css`、`src/season-music.js`：人生阶段、跨季章节、原创循环配乐与暂停／切换。

`state.total` 是路线长度40／12，`state.turn` 是实际完成的落点次数；不能把路线格数当成已经历事件数。历史同时记录路线位置 `position` 与完整地图事件索引 `tile`，保留三资源的前后值及实际变化。

存档使用 `snapshot.version = 4`、本地存储键 `four-seasons-life-v4`，包含角色名、天赋、骰子与选项日志。旧v1／v2／v3键保留。若早期v4记录误存于v3键，且新键尚不存在，则经过重放校验后复制迁移，旧记录不删除、不覆盖。真正的旧版记录不强制套用新规则。服务端不直接相信客户端余额。下载手记的位置由浏览器下载设置决定。
