# 强制登录后 5 局试玩与延迟检查

结论：5 局均能到达自然终局，4 局通关、1 局情绪归零提前结束；但不能判定整版验收通过。发现公网媒体间歇加载失败、开局重复验证登录，以及临时状态请求超时会把仍有有效会话的玩家退回封面。

## 测试边界

- 5 局使用正式公网 `https://zhihu-four-seasons.pages.dev` 的实际资源、真实 WebGL 和正常播放速度；不修改骰子、不注入游戏存档、不加速动画，逐局通过 UI 选择。
- 仅在隔离浏览器中模拟已登录状态，并将业务 API 注入 503，验证备用流程。**这不是 5 次真实 OAuth 登录，也不是 5 局实时 AI 质量／速度验收。**没有改变线上登录限制、产品代码或部署。
- 使用 1280×800、844×390 两种视口。浏览器自动选择省略了人的阅读与思考，测得的局长不能直接称为正常玩家耗时；音乐关闭，未验收音效质量。
- 单独的真实公网匿名探测与模拟会话故障测试分别记录，不能混作真实登录成功证据。
- 已另打开隔离的可见浏览器供用户本人授权，以测最多 3 次真实 AI。6 分钟内未观测到该测试窗口完成登录，已关闭；实际模型调用 0 次。此前用户确认自己的浏览器能登录仍是有效的用户反馈，但不等于本次隔离窗口测时成功。

## 发现的问题

### 1. 公网媒体和入口存在明显波动

5 局开始时实际 3D 资源就绪等待分别为 17.44、5.67、5.08、4.13、3.07 秒。这些是在当前测试环境观察到的加载时间，不是所有地区用户的保证值，也不是严格冷／暖缓存对比。

共观察 9 次影片出现，5 次自然播放结束、4 次未完整播放：

- 第 1 局：第 22、27 格影片各 0 帧，进入等待／停滞后切换备用演绎。
- 第 3 局：第 6 格 0 帧；第 27 格播放约 3.00 / 6.08 秒后停滞并切换备用。
- 第 6、22 格在后续局能正常播放，因此不能据此断言素材文件损坏。第 27 格本次没有完整成功样本。
- 第 1 局同时记录到 22／27 格封面及 idle／wave GIF 的网络超时、连接关闭或网络变化错误；未记录为 HTTP 404。

独立的匿名直连探测：首页 HTML 返回 200、耗时 7.39 秒；三个匿名业务请求正确返回 401，但分别耗时 2.03、7.38、14.54 秒，第四个请求传输失败。保留原失败后又作一次浏览器入口探测：DOM 加载约 23.05 秒，45 秒内未完成可操作入口等待。该探测没有走到 auth/start，**不能把此次公网登录验收写成通过，也不能把失败认定为知乎账号／回调配置错误**。

优先建议：针对目前媒体请求链路做稳定性定位，优化影片大小和加载时机、清晰呈现加载／备用状态；在不同真实用户网络补测固定地址，再决定是否更换托管方式。仅凭本机结果不承诺换服务器一定解决。

### 2. 有效登录也会因一次临时网络超时被退回封面

使用真实 main 与登录控制器、模拟服务器仍保持 authenticated=true；调用其实际注册的 60 秒检查回调，仅让这一次状态响应挂起，保留产品实际 8000ms 超时。

实测约 8.52 秒后从反馈页回到封面，提示“请登录知乎后继续，旅程进度已保留”。存档完整，点击重试和继续可以恢复，未再次授权。说明这是暂时无法验证身份，却被前端当成未登录处理，而不一定是账号真的掉线。

定位：`src/zhihu-auth-ui.js:124` 附近的失败状态清除身份；`src/main.js:169` 触发暂停回封面。建议将“确定未登录／过期”和“暂时网络失败”分开，网络失败先暂停需验证的操作并提示重新连接，保留当前画面；后台真实 401 仍应严格拦截，不能用改善体验为由放开游客入口。

### 3. 已登录开局会串行验证两次

实际集成测试中，初始化检查 1 次；随后只点击一次“走进我的四季”，又产生 2 次串行 status 请求。来源是 `src/main.js:314` 的 enterJourney() 验证后，又执行 `src/main.js:331` 的 start() 验证。

无须重新完成 OAuth，但在高延迟网络里增加一次完整请求等待。恢复旧旅途时，入口和点击“继续”也分别验证一次（中间有用户选择间隔，不应不加区分地删除所有校验）。建议先合并同一次新开局动作中的重复验证，保留会话有效性检查和独立入口保护。

## AI 和结局等待的证据边界

- 注入立即 503 时，第 1 局事件备用回顾约 184ms、总结备用约 67ms；两轮备用练习各约 35～291ms。表示已收到失败响应后备用呈现正常，**不能解释成真实 AI 在这些时间内生成**。
- `src/ai-client.js:31` 仍配置事件 25 秒、总结 50 秒的客户端上限；本次未测得真实总结生成时间。没有证明“之前约 50 秒等待”已消失。
- 首次结局截图在固定 650ms 时有大图空白；后续逐页解码全部成功。这是首帧等待／截图时机的证据，不是永久缺图。可考虑预加载结局图或显示加载占位。提前结束页“故事停在秋季 / 完整旅程”的后半句目前表示游戏模式，但容易被误读为已通关，可改成“40 站模式”等更明确的标签。

## 建议实施顺序

1. 分离登录状态未知与确定失效，减少网络抖动造成的退回封面。
2. 合并同一次开局里的重复身份校验。
3. 排查视频／首屏资源的公网传输波动，改善加载和备用表现。
4. 用户在隔离测试窗口完成授权后，再补真实总结和两轮陪练延时验收。
