## 实现与安全

- `POST /api/auth/zhihu/start`：必须同源，创建随机 32 字节、10 分钟有效的一次性 state，绑定当前浏览器的签名访客 Cookie。重新发起使旧邀请失效。
- `GET /api/auth/zhihu/callback`：接收 `authorization_code`（兼容单独的 `code`），拒绝缺失、重复、冲突、过期、跨浏览器和已使用的 state；事务消费后才请求知乎。
- `POST https://openapi.zhihu.com/access_token`：仅服务端表单提交应用凭证与授权码。
- `GET https://openapi.zhihu.com/user`：只发送 OAuth Bearer，先无损解析 int64 UID，再保存最少 ID、昵称；缺失昵称用“知乎旅人”，不拿空用户对象登录。支持历史成功 `code:20000`，不把 HTTP 200 当作必然成功。
- OAuth token 仅在服务端获取一次基础信息时短暂使用，随后不持久化；前端只持有不透明的随机会话 Cookie（HttpOnly / Secure / SameSite=Lax）。会话至多一小时，扣除上游处理耗时，不晚于 token 有效期。
- 登录/会话采用独立 DO 实例和独立持久化命名空间，不排队等待模型；上限限制和定时过期清理仍生效。
- `POST /api/auth/logout`：同源撤销会话、未完成邀请；退出中迟到的授权响应不能重新登录。状态到期后等待玩家主动登录，不自动反复授权。
- 后端及内部 Service Binding 的重定向均显式处理，303 与 Set-Cookie 交给浏览器；不把应用凭证带往其他 host，不接任意 return URL。
- 所有授权页/接口 `no-store`、`no-referrer`；错误不回显 code、state、上游响应、App Key 或 token。现有日志观测仍关闭。
- 主入口仍只有“走进我的四季”；按用户最新要求，未登录点击该入口先完成知乎授权。账号控件只在登录后显示昵称与退出，游戏内在原有玩法窗口管理账号。昵称不会被知乎昵称覆盖，跳转前只临时保存自填昵称/天赋草稿，返回后一次性清除，不保存 OAuth 数据。
