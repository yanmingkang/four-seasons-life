# 手机按电脑画面等比缩放 · 2026-09-14

## 本轮要求

用户要求以提供的 1904×942 电脑截图为准，手机横屏只整体缩小，不改变展示形式、字体设置或各部分比例。前两轮的横排心态卡、单独调整字号与间距不再作为当前方案。

## 实现

- `#game-frame` 对应浏览器真实可视区域，扣除刘海和底部安全区。
- `#app` 在短横屏使用固定 **1904×942** 的逻辑画布。倍率为 `min(可用宽/1904, 可用高/942)`，居中显示；比例不同留边，不拉伸、不裁切。
- 封面、人物、状态栏、地图和全部按钮共享同一次缩放。心态保持电脑端的上下三项，字体家族、逻辑字号、字重和行高不单独改写。
- 组件的尺寸媒体查询改为查询逻辑画布，视口单位改为画布单位；原 CSS 的字体、颜色、卡片结构不因手机物理宽高触发另一套布局。旧 `mobile-cover.css` 与 `mobile-full-chrome.css` 已停止导入。
- Windows 参考桌面预留的 10px 细滚动条槽，在使用浮动滚动条的手机封面中显式保留，避免左右两栏因平台滚动条差异而变宽。
- 原生 `dialog.showModal()` 继续保留焦点锁和背景遮罩，弹窗在浏览器顶层独立使用相同倍率与居中位置。
- 3D 标签避让和拖动输入换算屏幕与逻辑坐标，点击拾取仍使用实际画面边界。未改骰子、剧情、资源、存档、OAuth 或 AI 接口逻辑。
- 昵称输入、键盘收缩、横竖切换与安全区变化重新计算统一倍率；保留浏览器原生捏合缩放。竖屏仍显示原来的横屏提示。

启用范围：横屏、可视高度不超过 650px，且宽度不超过 1400px 或为触屏。正常电脑窗口继续使用其真实尺寸；1904×942 电脑参照布局不变。

## 验收方式

修改前先保存了四种状态的真实 Chrome 电脑几何和字体基线，随后才转换样式。新版本既与旧电脑基线比较，也将每个手机元素的位置和尺寸按倍率反算回电脑；不是只检查“按钮可见”。

- 等比浏览器验收 **28/28 通过**：4 个电脑状态、20 个手机状态、2 组连续横竖切换、安全区与键盘各 1 组。
- 每屏比较 74／76 个元素的坐标、宽高、原文及四项字体设置。三选项和开始入口无须滚动，选择、昵称、继承开关和已有存档保持。
- 每组手记弹窗也按同倍率检查位置，并使用屏幕坐标真实点击开关。
- 3D 旋转在 1、0.25、0.5 倍时，相同比例的拖动得到相同旋转角；坐标 helper 与标牌单测通过。
- 强制登录回归 **12/12 通过**，全部使用模拟 API；不据此声称新增真实授权或 AI 延迟验收。
- 移动布局回归 **11 组、114 项通过**：包含完整封面、键盘、医院事件、两轮陪练、回忆册和分享按钮，以及运行期间改变安全区的检查。
- 单元测试 **732 项：731 通过、1 跳过、0 失败**；生产构建通过。

上述使用桌面 Chrome 的真实 WebGL 与手机触摸/尺寸模拟，不是实体微信全机型测试。等比缩小也会等比缩小文字，这是本轮明确选择的完整电脑构图；不会再次擅自放大部分字、隐藏内容或改变卡片排列。各手机实际使用的系统字体仍取决于系统是否具备对应字体。
