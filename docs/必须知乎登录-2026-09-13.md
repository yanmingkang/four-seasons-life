# 必须先登录知乎，再开始四季旅程

## 用户确认与范围

用户已确认赛事后台保存了固定回调 `https://zhihu-four-seasons.pages.dev/api/auth/zhihu/callback`，并在入口开启后亲自回复“已登录”。这是用户提供的真实授权结果，独立于自动化模拟验收；Agent 没有读取用户浏览器 Cookie、授权码、账号密码或访问令牌。

随后用户要求取消“知乎登录（可选）”，改为游戏必须登录才能玩。本次沿用现有 App ID、Worker Secret、Pages 稳定域名和 SQLite 会话，不重新索取凭证、不接入付费服务，也不扩展到关注、收藏、手机号等权限。

## 交互规则

- 封面仅保留“走进我的四季”主入口。匿名点击时先核对状态并跳转知乎授权，不创建新局、不覆写旧存档。
- 已登录后才允许开始新局、恢复旧旅程或重开；进游戏前重新核对服务器状态，不能凭 URL 上的 `auth=success` 或本地标记放行。
- 登录状态加载失败或接口未开放时停留封面，可以主动重试，不提供游客继续，也不自动反复跳转。
- 登录失败不会丢掉玩家填写的昵称；知乎昵称仍独立显示，不覆盖玩家给旅人起的名字。
- 游戏中退出、会话失效或无法确认会话时保存现有进度，停止自动出发、动画与在途叙事，回到封面。重新登录后可从原入口恢复，不自动开新局。
- 封面和玩法窗口只在已登录时显示账号及退出按钮；没有第二个匿名登录选项。

## 服务端边界

云端点评、总结、两轮陪练、知乎搜索及 AI 状态等业务接口也必须校验有效的服务端 OAuth 会话。匿名或失效请求返回固定 401，不进入模型调用或游戏额度逻辑。登录相关接口、首页、静态素材和健康检查保持可访问，避免形成登录重定向循环。

游戏存档仍是本机浏览器存档，不是知乎账号云存档；本次不承诺跨设备同步。前端控制负责正常玩家流程，服务端会话校验负责业务接口权限，不能将公开的 JavaScript/美术资源描述为不可下载的加密资源。

## 状态请求的 HTTP/2 兼容补丁

只读对照在新建浏览器上下文运行，无账号密码、授权、POST 或业务调用。默认 Chrome 在有/无 Playwright 网络拦截时均出现第二次相同 URL 正文等待超时，排除了仅由测试拦截产生的解释；HTTP/1.1 两次正常。保留正常游戏页面，在默认 HTTP/2 下给两次 status 请求各加不同 `check` 参数，也两次完整返回（2.689 秒、0.651 秒）。Node 同一访客 Cookie 的重复读取正常。证据支持当前浏览器/链路重复 URL 路径异常，尚不能确定具体是哪一层。

据此仅给前端 `GET /api/auth/status` 增加每次独立的非隐私防缓存参数 `check=时间戳base36-递增序号`，不持久保存；它不是 OAuth `state`、登录凭证或用户标识。服务端仍按精确路径与会话判断，8 秒超时、同源、`no-store`、失败锁定和每次入场验证均保留；授权开始 POST 与已登记回调不增加参数。本地 12 项浏览器流程在补丁后再次全部通过。

协议对照保留在 `test-results/zhihu-status-stream-diagnostic/`；最终线上验收另写 `test-results/zhihu-mandatory-public-cachefix/report.json`，不覆盖先前失败记录。

补丁已按先 Pages、后 Worker 的顺序发布成功：Pages `90b294e8`，Worker `dc0fdfd6-bf2f-4dee-890a-8bfd8d0edb78`，当前入口 `/assets/index-DgducxrI.js`、主脚本 `/assets/main-BKfhGrAe.js`。不更换稳定公网域名或回调，不新增 Secret、OAuth 权限或付费资源。
