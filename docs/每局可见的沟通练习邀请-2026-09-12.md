# 每局可见的沟通练习邀请

## 交付规则

- 骰子仍使用原来的六面随机规则，未修改掷骰、落点、资源、疲惫或称号规则。
- 正常结算第 11 / 13 格时，保留该事件的原练习入口；已出现过这些入口，就不再补独立邀请。
- 完成第三次事件结算后，若还没见过邀请，在反馈页前部出现一次可跳过的邀请。不是“第 3 格”，也不要求玩家踩到指定格。
- 邀请明确标为“沟通小练习 / 独立假设情境”，按钮为“试着说一句 / 继续旅行”。
- 继续旅行只执行原有反馈到准备页的推进，不多结算一次。接受练习也不改变资源、历史、骰子、结局或称号。
- 终局时如果此前没见过邀请，只在四季回忆册顶部保留入口，不自动弹出练习；X、Escape、完成或跳过均回到原回忆页。
- 独立邀请接受或跳过后不再显示；仅看见但尚未处理时刷新，会保留同一张待处理卡，不发出第二次邀请。之后自然重点格的入口仍可使用。
- 新局重新计算邀请。旧存档根据实际已结算的 11 / 13 格保守恢复入口已出现状态，不推断玩家完成过练习。

## 数据与 AI 边界

邀请状态只放在存档顶层 `practiceInvitation`，不进入引擎 `game` / `history`、回忆数据或分享图片。对话仍为临时会话，不保存到正式旅程。

新增请求为 `rehearsal: { id: 'cross-team-invite-v1' }`，与 `game`、`sample` 严格互斥。服务端提供固定的假设准备情境，不接收伪造落点、选择或经历；会话命名空间与原样板、正式事件隔离。

玩家实际发送文字才请求模型，最多两轮。失败时明确标识“预设练习 · 非实时 AI”，允许随时退出。
