## 3. 失败备用：通过

### 真实服务端失败路径（不联网）

另一独立服务将 CLI 指向明确不存在的路径：

- 事件回顾、总结返回 `fallback`，有可读正文。
- 两轮陪练返回 `fallback`，第二轮有方法提示；重复请求保留 fallback 标识。
- 搜索返回 `curated`，保留事先整理的知乎来源。
- 非法第三轮和改写已完成轮次仍被拒绝。
- 此组真实业务 API 调用为 0。

### 浏览器专项（全部 API / 外网拦截）

Windows Chrome、1280×800、原生 D3D11 WebGL、独立浏览器存储；测试未加速时钟。三组均通过，6 张截图已目视检查：

1. 总结 HTTP 503 与实际 50.058 秒客户端超时：切换为“备用回顾 · 预设内容”，未冒充实时 AI；等待及失败期间都能下载保留本局历史的手记、返回回忆册，重新打开不会重复请求。
2. 陪练 HTTP 503：第一轮失败后明确转入两轮本地预设，第二轮不再重复请求；可以收下方法并返回旅程，资源与历史不变。
3. 搜索 HTTP 503 与实际 15.510 秒客户端超时：已整理的原文链接仍在，手动重试按钮可用。

## 5. 建议后续优化（本次未擅自改动）

- 总结断网悬挂时等待约 50 秒，现场体验偏久。可先显示明确标记的本局预设回顾，并允许玩家主动继续等待或重试，而不是一直等待生成。
- 生成文案还可更紧凑：事件 87 字符 / 79 汉字，符合建议的 40–80 个中文字；总结 189 字符 / 167 汉字，略超建议的 100–160 个中文字，未超过现有 250 字符展示上限。总结中的“慢生活那笔投入”虽随后明确只做考察，改成“慢生活的投入打算”会更准确。
- 搜索结果主题相关性不一：此次前两条直接讨论工作留痕，第三条偏向工作呈现技巧。可再做相关性筛选；不能把搜索结果自动称为已核实依据。
